# Execution replay

## What this verifies

`scripts/replay_episode.py` is an operator-only execution audit. It creates a
new disposable episode, reruns recorded actions, and compares results against
the original record. The existing V2 replay HTTP endpoint remains a structural
verifier; its contract and the Agent gateway are unchanged.

These checks are different:

| Check | Executes tools again? | Establishes |
| --- | --- | --- |
| Cached retry / restart | No | Idempotency and persisted response recovery |
| Existing structural replay endpoint | No | Recorded state/trace consistency |
| This execution replay CLI | Yes | Supported recorded actions reproduce outputs under the audited current runtime |
| Rendered WorldCover execution replay | Yes, with explicit fresh renderer and evaluator inputs | Deterministic render bytes and the recorded semantic evaluation are recomputed |
| Model replay | No | Repeated model reasoning and action selection are not established |

## Supported boundary

The current adapter supports terminal headless episodes using
`catalog.search@1.0.0`, `catalog.inspect_asset@1.0.0`, `eo_gym.crop@1.1.0`, and
`raster.band_math@1.0.0`/`1.1.0` (reviewed native or SCL-policy-masked NDVI), plus
`raster.resample@1.0.0`/`1.1.0` (categorical nearest or reviewed continuous
bilinear alignment) and `raster.zonal_stats@1.0.0` over an episode-local
continuous artifact. Scientific replay additionally
requires `--raster-provider` and an actual `--raster-provider-instance`; see
[native-raster-tools.md](native-raster-tools.md) for the isolated recipe and
three-date 14-action grid and 20-action chained positive/offline-negative evidence.
It also supports the deterministic `rendered-worldcover-v1` profile when the
operator supplies a fresh renderer URL and inspected container ID, the pinned
renderer config, and a read-only evaluator dataset root. Renderer captures are
regenerated and checked as exact artifact metadata/content. The evaluator runs
again against the fresh artifacts and canonical dataset. It uses the original
episode's persisted wall-time accounting when recomputing `process.efficiency`;
current replay-machine speed is separately reported and cannot silently change
the historical metric.

Non-tool actions are rerun through the ordinary domain reducer, including
evidence, submission/abstention and deterministic recorded rejection. Unsupported
tools/versions, active episodes, pending tools, historical tool failures,
or rendered/evaluated profiles without their explicit adapters return `incomplete`.
They never count as a successful partial replay. Current execution/output
differences return `failed`; the CLI exits 2 for either non-passing status.

Only accepted, persisted actions are covered. Unrecorded preflight rejections,
transport retries and the model's selection of an action are not reconstructed.
Recorded tool failures need a future explicit fault-injection adapter. Wall-time
usage is excluded from equality, but the limit and actual budget enforcement
remain active; timing-sensitive expiry can therefore fail reproduction.

## Original-state and comparison checks

- Open the original SQLite database with `mode=ro`, `query_only=ON`, and a
  consistent read transaction. Do not initialize, migrate or recover it.
- Bound the snapshot to 128 results/tool runs/artifacts, 129 observations,
  4,096 events and 32 MiB of JSON before loading the payloads.
- Validate task pins, episode identity/status, ordered event identities,
  accepted-action/result coverage, exact requests, observations and tool versions.
- Recreate a store with the same task and seed, then execute each recorded action
  in accepted-event order against a separate provider. Do not copy cached results
  or read original artifact blobs as output.
- Compare every action outcome and normalized response, final state, full
  normalized event sequence, artifact metadata/lineage and newly generated bytes
  against recorded SHA-256 and size. Evidence IDs, answers, tool arguments and
  inline outputs remain significant, including fields named like timestamps.
- Exclude regenerated episode/observation/event/evaluation IDs, observation-ref
  lists, timestamps, raw state hashes and wall-time usage from normalization.
  Metric values, evaluator status/version, grounded diagnostics and aggregate
  reward remain significant. This is field-normalized execution equality, not
  bit-identical whole-database reproduction or repeated model reasoning.
- Reread original logical state and task pins after replay. Record current source
  hashes, package versions and the pinned upstream revision before/after.

Historical dependency/container identities were not recorded by earlier runs.
Reports therefore retain `historical_runtime_environment_verified=false` and
`model_reasoning_replayed=false`. The supplied provider ID is operator-inspected,
not a remote attestation; the same applies to renderer IDs. For trustworthy acceptance, operators must use the
isolated deployment below and record the real container ID, empty output
directory, and actual `/execute` request count.

## Isolated A800 recipe

Prerequisites: the existing rootless API image, pinned EO-Gym runtime dependencies,
initialized runtime quota ledger, a stopped original episode writer, and reviewed
image-only inputs prepared by the Agent smoke. No installation or download is
performed by replay. Reuse the A800 system proxy for any separate acquisition.

Use an unused report name and a dedicated Compose project. Do not start the
original Harness, gateway or storage service for this audit. The provider has
only reviewed image inputs and upstream source, not tasks, original DB or labels.
It runs on an internal network with no published ports. Each crop launches a
fresh bounded CPU worker; output publication may deduplicate bytes only after
the worker has executed.

```bash
cd /sata/yangm/eo-harness
export EO_SMOKE_ROOT=./runtime/agent-xlrs-20260917-01
export EO_REPLAY_EPISODE=ep2-79b19dff038c4b05b897fb490c91e5a8
export EO_REPLAY_RUN=execution-agent-new-audit
# Reserved only as a parse-time placeholder for the provider-only start.
export EO_REPLAY_PROVIDER_ID=not-yet-inspected
docker --context rootless compose -p eo-harness-execution-new \
  -f compose.eo-gym-smoke.yaml -f compose.execution-replay.yaml \
  up -d --wait provider
docker --context rootless inspect eo-harness-execution-new-provider-1 \
  --format '{{.Id}}'
docker --context rootless exec eo-harness-execution-new-provider-1 ls -A /outputs
# Replace this with the exact inspected 64-character ID, never a made-up ID.
export EO_REPLAY_PROVIDER_ID='replace-with-inspected-container-id'
docker --context rootless compose -p eo-harness-execution-new \
  -f compose.eo-gym-smoke.yaml -f compose.execution-replay.yaml \
  run --rm --no-deps replay
docker --context rootless logs eo-harness-execution-new-provider-1
docker --context rootless compose -p eo-harness-execution-new \
  -f compose.eo-gym-smoke.yaml -f compose.execution-replay.yaml \
  --profile replay down
```

For a rendered WorldCover episode, mount the original DB/tasks and canonical
dataset read-only, join the fresh renderer's internal network, and add these
arguments to the same operator CLI. `--renderer-instance` must be the inspected
64-character container ID, not a service name or image tag.

```text
--renderer-url http://renderer:8090
--renderer-instance <inspected-container-id>
--renderer-config /workspace/config/v2/renderer.json
--datasets /datasets
```

Do not mount the original artifact store. Stop the renderer for the offline
negative, use a fresh report path, and expect `renderer_unavailable` on the first
rendering action. The renderer config file hash and current evaluator/renderer
source hashes are included in the replay runtime fingerprint.

The original DB/tasks are read-only mounts. Fresh replay DB/artifacts occupy
a disposable 512 MiB tmpfs; provider cache is 128 MiB and worker scratch 256 MiB.
The report has a 1 MiB cap and a 2 MiB shared-ledger reservation, refuses overwrite,
and remains at `runtime/<EO_REPLAY_RUN>/execution.json`. Existing data and reports
are preserved by Compose down. Docker logs and other legacy writer growth still
need their separate quota work; this is not a whole-host disk quota.

For a negative test, stop only this audit's provider, choose another fresh report
name and rerun the CLI. Expected: `failed`, exit 2, and `tool_unavailable` at the
first crop. Restarting the provider or reading old blobs must not mask that failure.
